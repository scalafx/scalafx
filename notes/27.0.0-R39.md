This release is primarily to add support for features added in [JavaFX 27].

This release supports [JavaFX 27]. It was tested with Java 25, 26, and 27. It can be used with Scala 2.12, 2.13,
and Scala 3.3+.

Note that [JavaFX 27 requires Java **25 or later**][JavaFX 27]. If you need to run on Java earlier than 25, please use
previous releases of JavaFX/ScalaFX.

### Details

#### JavaFX 27: `HeaderBar` API changes (breaking)

In JavaFX 27, `HeaderBar` and `StageStyle.EXTENDED` graduated from preview features to final API. It is no longer
needed to run with `-Djavafx.enablePreview=true` to use them. As part of that, JavaFX 27 renamed some of the `Stage`
attached properties of `HeaderBar`. ScalaFX follows the JavaFX naming, the old ScalaFX methods were removed:

| Removed (ScalaFX 26)                          | Replacement (ScalaFX 27)                        |
|-----------------------------------------------|-------------------------------------------------|
| `HeaderBar.prefButtonHeight(stage)`           | `HeaderBar.systemButtonHeight(stage)`           |
| `HeaderBar.getPrefButtonHeight(stage)`        | `HeaderBar.getSystemButtonHeight(stage)`        |
| `HeaderBar.setPrefButtonHeight(stage, value)` | `HeaderBar.setSystemButtonHeight(stage, value)` |
| `HeaderBar.minSystemHeight(stage)`            | `HeaderBar.systemMinHeight(stage)`              |
| `HeaderBar.getMinSystemHeight(stage)`         | `HeaderBar.getSystemMinHeight(stage)`           |

New in JavaFX 27 is `HeaderBar.systemColorScheme(stage)` (with `getSystemColorScheme` and `setSystemColorScheme`).
It specifies the color scheme of the system-provided header buttons. By default, it follows the scene color scheme.
Setting it to `ColorScheme.Light` or `ColorScheme.Dark` overrides the scene color scheme, setting it to `null` restores
the default:

```scala 3
// Dark header buttons, regardless of the scene color scheme
HeaderBar.setSystemColorScheme(stage, ColorScheme.Dark)
```

See `HeaderBarColorSchemeDemo` in `scalafx-demos` for a complete example.

#### Decouple media/web from blanket scalafx.Includes import

If your project excludes javafx-media and/or javafx-web from its build, swap your blanket import `scalafx.Includes.*`
for the `scalafx.CoreIncludes.*`:

```scala 3 
// Before — requires javafx-base/graphics/controls/fxml and javafx-media/swing/web on the classpath

import scalafx.Includes.*

// After — only needs javafx-base/graphics/controls/fxml
import scalafx.CoreIncludes.*
```

`CoreIncludes` gives you all includes in base/graphics/controls/fxml/swing, minus the ones tied to `javafx.scene.media`,
`javafx-swing`, and `javafx.scene.web`. If you do use MediaView/MediaPlayer, Swing, or WebView somewhere, just add the
matching trait alongside it in that file, as needed:

```scala 3
import scalafx.CoreIncludes.*

import scalafx.scene.media.MediaIncludes.* // only where you use media APIs

import scalafx.scene.media.SwingIncludes.* // only where you use swing APIs

import scalafx.scene.web.WebIncludes.* // only where you use WebView
```

Existing code using `scalafx.Includes.*` keeps working unchanged — Includes still aggregates CoreIncludes +
MediaIncludes + WebIncludes for backwards compatibility. This is purely opt-in and doesn't change ScalaFX's own
dependencies or require any `build.sbt` changes on your end.
